## 审核口径：以课程课件为主（2026-11-21 更新）

**审核依据优先级**

1. **授课课件／课件例题优先**：先核对 PPT 的定义、符号、推导、图表及答案形式；网站应尽量延续课程的教学顺序和术语，不因外部资料说法不同就重写课件。
2. **课件自身有明显错误时明确标注**：保留“PPT 原文是什么”的信息，在对应正文附近设置“课件勘误/表述提示”，注明正确解释和复习时该记什么；不将课件笔误伪装成网站抄录错误。
3. **原卷与教师答案的判分口径单列**：原卷题干原则上不改。课程简化模型或旧式子网规则可能影响选项时，**先保留有依据的课堂答案**，再在解析中补充适用条件。尚未拿到教师正式评分依据的争议题继续保持待确认。
4. **课件未涉及的现代标准作为拓展**：例如 HTTP/3、10GBASE-T、EDNS(0)、VLAN 扩展实现等，用“补充/现代标准”标记，**不得冒充课件原文**，也不自动作为期末考试判分依据。
5. **可追溯但不公开私人资料**：在本仓库只引用课件章节或页码，不放 Google Drive URL、文件 ID、个人目录路径。凡标注“已核对课件”的条目必须有实际读到的课件内容支持，不能由猜测补写。

## 追加发现的标准层面错误（同属本次修订）

- [ ] C44 `ch4.ts` CRC 余数为 0 并不等于“绝对无错”，应表述为“未检出差错”，仍可能漏检。
- [ ] C45 `ch6.ts` 快恢复原先写“ssthresh 减半后，又将 cwnd 设置为 ssthresh 减半后的数值”，语义可能误读为两次减半。现按 2025 传输层第132页的课堂简化模型明确：`新 ssthresh = 原 cwnd / 2`、`新 cwnd = 新 ssthresh`；答案仍为 12KB。
- [ ] C46 `ch7.ts` QUIC 的长短首部不同，Packet Number 等字段有头部保护，不能说首部所有字段一律明文；帧名称使用标准的 MAX_DATA 等。
- [ ] C47 `ch7.ts` 0-RTT 并非首次安全连接即可启用，要求此前连接的恢复凭据，且可能受到重放攻击影响。以上两条是 **RFC 9000 / TLS 1.3 标准核查**，2025 应用层 PPT 不覆盖这些细节。

- [ ] **C56** `ch4.ts` “超出 MTU 发送方必然分片”→区分 IPv4 在允许时分片、IPv4 DF 丢弃，以及 IPv6 路由器不进行中途分片。**协议标准核查**。

### 第5章 网络层

- [ ] **C57** `ch5.ts` 在“IPv4 首部格式”表中说 version=6 就按同一表解释为 IPv6 → 明确 IPv6 有不同的首部结构。[RFC 8200](https://www.rfc-editor.org/rfc/rfc8200)。
- [ ] **C58** `ch5.ts` IPv4 的“区分服务”8 位字段被描述为“未使用，包含 D、T、R”→更新为 **DSCP 6 位 + ECN 2 位**。**PPT 仅讲 DiffServ 字段，具体位定义按** [RFC 2474](https://www.rfc-editor.org/rfc/rfc2474)、[RFC 3168](https://www.rfc-editor.org/rfc/rfc3168)。
- [ ] **C59** `ch5.ts` RIP 的距离度量表述模糊 → 说明主要是跳数，典型每跳 1，部分实现允许人工配置接口代价，但不是自动按时延/带宽加权。**按** [RFC 2453](https://www.rfc-editor.org/rfc/rfc2453) **及实际实现补充**。
- [ ] **C60** `ch5.ts` 路由过程第四步 “找不到目标路由必然走默认路由” → 改成仅在**有默认路由**时才转发，否则丢弃。
- [ ] **C61** `ch5.ts` 同一节另一段重复“找不到必然走缺省路由”→ 同步修复，消除前后矛盾。
- [ ] **C62** `ch5.ts` 所有联网设备必有全球唯一 IPv4 地址 → 说明私有 IPv4 地址可以在不同内部网中重复使用，NAT 也会共享公网地址。
- [ ] **C63** `ch5.ts` ARP 报文的 SHA、SPA、THA、TPA 被写成拆开的前/后几字节“字段”→ 更新为按顺序排列的连续 6/4/6/4 字节地址字段。**按** [RFC 826](https://www.rfc-editor.org/rfc/rfc826) **核查**。

### 第6章 传输层

- [ ] **C64** `ch6.ts` “UDP 无论应用层给多大报文都照样发送” → 说明保留报文边界但受 UDP/IP 报文长度及 MTU 限制。
- [ ] **C65** `ch6.ts` 把 DNS、DHCP 以 UDP 进行的请求—响应等同于 RPC 应用 → 说明 RPC 是远程过程调用模型，二者不是仅因使用 UDP 就成为 RPC。
- [ ] **C66** `ch6.ts` “延迟 ACK 就是累积确认” → 分开定义：延迟 ACK 是确认发送时机策略，累积确认是确认号的语义，不能混同。[RFC 9293](https://www.rfc-editor.org/rfc/rfc9293)。
- [ ] **C67** `ch6.ts` “TCP 每发一个报文段就为它设立独立计时器” → 改为通常维护针对最早未确认数据的重传计时器，不机械地按段设独立计时器。**TCP 实现/规范核查**。

### 第7章 应用层

- [ ] **C68** `ch7.ts` DNS 响应 TC=1 被解释为“一定超过 512 B” → 明确 TC 表示截断，使用 EDNS(0) 时 UDP 响应上限可大于 512 B。**DNS 协议扩展核查**。
- [ ] **C69** `ch7.ts` DNS 高速缓存记录统一“只存两天” → 改为按记录 TTL 处理，而不是固定保存时间。
- [ ] **C70** `ch7.ts` DNS 递归解析遇到本地无答案就必定先问根服务器 → 补充本地缓存、已有委派信息可能直接确定下一跳；原 PPT 图示为简化流程。
- [ ] **C71** `ch7.ts` HTTP/1.1 流水线“访问所有对象只需一个 RTT”表述过于绝对 → 补充已建立连接、忽略响应传输时间等理想化前提。
- [ ] **C72** `ch7.ts` HTTP/2 的握手成本混淆 TCP 三次握手、TLS 握手和多路复用成本，写“TCP 1.5 RTT + TLS 1-2 RTT + 多路复用 1 RTT” → 区分正常开始应用数据约 1 RTT 的 TCP 建立、TLS 1.3 全握手通常再需约 1 RTT，复用并非固定额外 1 RTT。

### 数据链路层：窗口、网桥、VLAN

- [ ] **C73** `ch4.ts` 选择重传窗口条件将 `W_T ≥ W_R` 和 `W_T + W_R ≤ 2^m` 都写成硬性必要条件。已区分：后者是避免新旧序号混淆的约束，前者主要是避免接收窗口容量闲置的效率建议。对应 P20。
- [ ] **C74** `ch4.ts` 回退 N 发生超时“必定重发这 n 帧”→从最早未确认帧起重传**仍未确认**的帧，数量不必恰为发送窗口上限 n。
- [ ] **C75** `ch4.ts` 透明网桥 MAC 表“每发送或接收一个帧就刷新时间戳”→通常在从接收帧**源 MAC** 学习/刷新表项时更新老化计时；单纯向目标 MAC 转发不等于学习该目标。
- [ ] **C76** `ch4.ts` “每个 VLAN 的帧都会插入 802.1Q 标签”→仅在需要的标记链路使用，接入端口通常无标签，Trunk 的 native VLAN 也可能无标签。**标准与设备实现核查**：[Cisco VLAN Trunk 指南](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html)。
- [ ] **C77** `ch4.ts` “VLAN 隔离广播风暴和冲突”混淆机制→VLAN 分隔**广播域**；交换机端口分隔**碰撞域**。对应 P18。
- [ ] **C78** `ch4.ts` “VID (0—4095) 都是普通 VLAN 号”→12 位字段可编码 0—4095，但 **0 用于优先级标记、4095 保留**，通常可分配的 VLAN ID 为 1—4094。[Cisco VLAN 配置文档](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan.html)。

### 传输层、应用层

- [ ] **C79** `ch6.ts` TCP URG/紧急指针被解释为“高优先级数据保证”及“紧急数据共有多少字节”→明确它是相对序号偏移，指向紧急数据之后第一个字节的序号；非 QoS 优先级机制。[RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html)。
- [ ] **C80** `ch6.ts` “TCP 接收窗口大小不为 1，通常与发送窗口一样大”→接收窗口按**字节**通告，可为 0 或 1，不必等于对端实际发送窗口。[RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html)。
- [ ] **C81** `ch7.ts` HTTP 一律通过 TCP 传输 → HTTP/1.1、HTTP/2 通常使用 TCP；**HTTP/3 使用 QUIC/UDP**，前后章节应保持一致。[RFC 9114](https://www.rfc-editor.org/rfc/rfc9114)。
- [ ] **C82** `ch7.ts` IMAP “离线状态下连接已经终止，客户端还可以发命令”→区分**Logout 注销状态**与邮件客户端的离线工作模式，注销/连接关闭后不能再在原连接发送命令。[RFC 3501](https://www.rfc-editor.org/rfc/rfc3501)。
