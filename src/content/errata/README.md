# 读者勘误

每个 `*.json` 是一次提交产生的勘误补丁，由站点顶栏的「勘误」入口生成：
读者在正文上原地改完 → 审阅弹窗逐条核对 → 生成 PR（直接开 PR，或由 GitHub
自动 fork 后开 PR）。

## 文件格式

```json
{
  "version": 1,
  "id": "20261123-091011-a1b2",
  "createdAt": "2026-11-23T09:10:11.000Z",
  "pageTitle": "第1讲 绪论与算法设计思维",
  "note": "教材 P12 的复杂度有误",
  "changes": [
    {
      "page": "/algo/deck/deck1",
      "anchor": "3.4 复杂度分析",
      "old": "原文里那一段完整文字",
      "new": "订正后的同一段文字",
      "occurrence": 0
    }
  ]
}
```

- `page`：HashRouter 路由（不带 `#`），如 `/os/chapter/ch1`。
- `anchor`：最近的章节 h2 文案，用于缩小区间；缺失时全页查找。
- `old` / `new`：**该文本单元的完整 textContent**（纯文本，实体已解码）。
- `occurrence`：同一锚点下 `old` 相同文本里的第几个（0 起），缺省 0。
- 一处改动一个 change；一个文件可含多页、多处改动。

## 合并之后

构建时 `src/content/errata.ts` 会把本目录全部 JSON 打包进来；页面渲染后
逐条按 `page` 过滤、按 `createdAt` 顺序套用。匹配不到（内容已改版或已被
其他勘误改动）时静默跳过，不会误改别的位置。

运行时替换只动文本节点，`<strong>`、`<a>`、上下标等行内结构原样保留。
被订正的段落会带 `data-errata-fixed` 属性，便于排查。

## 维护

勘误只是叠加层：不改动 `src/content/**/*.ts` 里的原始 HTML，也不进搜索索引。
如果希望把订正落回原文，按 `old` → `new` 手工改写对应内容文件，然后删除
相应 JSON 即可（两者同时存在也不会重复生效）。
